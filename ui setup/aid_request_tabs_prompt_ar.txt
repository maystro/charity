برومبت تنفيذ نموذج إدخال طلب مساعدة بنظام التبويبات
مخصص لوكيل البرمجة: GPT-5.4 Mini
المشروع: نظام إدارة منشأة خيرية
المرحلة الحالية: تنفيذ نموذج طلب مساعدة وربطه بالأسر والبحوث الاجتماعية
بيئة العمل: Laravel 13 + Livewire + MySQL
لغة الواجهة: العربية RTL

============================================================
1) الهدف العام
============================================================

نفّذ نموذجًا احترافيًا لإدخال طلب مساعدة لأسرة مسجلة في النظام، على أن يكون مقسمًا إلى تبويبات واضحة، ويعمل داخل نظام الصفحة الواحدة الحالي دون Full Page Refresh، مع الحفاظ على البيانات عند الانتقال بين التبويبات.

دورة العمل المطلوبة:

اختيار الأسرة
→ التحقق من صلاحية آخر بحث اجتماعي
→ إدخال بيانات الطلب
→ إضافة بنود المساعدة
→ رفع المستندات
→ مراجعة الطلب
→ حفظه كمسودة أو إرساله للمراجعة

لا تنفذ الآن:

- قرار لجنة الاعتماد.
- الاعتماد الكلي أو الجزئي للبنود.
- الصرف أو التنفيذ.
- رسائل واتساب للمتبرعين.
- تحصيل التبرعات.
- النظام المالي أو المخازن.

لكن جهّز البنية لتدعم هذه المراحل لاحقًا دون إعادة بناء النموذج.

============================================================
2) قواعد إلزامية قبل التنفيذ
============================================================

1. افحص المشروع الحالي والـUI Framework المنفذ سابقًا.
2. استخدم مكونات الواجهة الحالية ولا تعِد تصميمها.
3. استخدم Blade/Livewire Components الحالية مثل:
   - x-ui.button
   - x-ui.input
   - x-ui.select
   - x-ui.searchable-select
   - x-ui.tabs
   - x-ui.card
   - x-ui.alert
   - x-ui.badge
   - x-ui.file-upload
   - x-ui.modal
4. إذا احتجت مكونًا غير موجود، أنشئه أولًا داخل UI Kit ووثقه.
5. لا تكتب عناصر متكررة بكلاسات Tailwind طويلة داخل الصفحة.
6. لا تغير الثيم أو درجات البني أو أحجام الواجهة الحالية.
7. استخدم wire:navigate في الروابط الداخلية.
8. لا يوجد Full Page Refresh داخل النموذج.
9. أنشئ قبل التنفيذ:
   - AID_REQUEST_IMPLEMENTATION_PLAN.md
10. حدّث بعد كل مرحلة:
   - PROGRESS.md
   - TASKS.md
   - DECISIONS.md
11. أنشئ توثيقًا نهائيًا:
   - AID_REQUEST_FORM.md

3) المسارات والشاشات
============================================================

المسارات المقترحة:

GET /aid-requests
GET /aid-requests/create
GET /aid-requests/{aidRequest}
GET /aid-requests/{aidRequest}/edit

الشاشات المطلوبة:

1. قائمة طلبات المساعدة.
2. إضافة طلب مساعدة.
3. تعديل مسودة أو طلب معاد للاستكمال.
4. عرض الطلب للقراءة فقط.

استخدم Route Model Binding وسياسات Authorization واضحة.

4) هيكل صفحة النموذج
============================================================

تتكون الصفحة من:

1. Page Header.
2. شريط مختصر لمعلومات الطلب والأسرة.
3. شريط التبويبات.
4. محتوى التبويب الحالي.
5. شريط إجراءات ثابت أسفل النموذج.

Page Header:

- العنوان: إضافة طلب مساعدة.
- وصف: تسجيل احتياج جديد لأسرة مسجلة ومعتمدة.
- زر العودة لقائمة الطلبات.
- حالة الطلب.
- رقم الطلب بعد إنشائه.

بعد اختيار الأسرة اعرض شريط معلومات يحتوي على:

- اسم رب الأسرة.
- كود الأسرة.
- الفرع.
- المندوب المسؤول.
- درجة الاستحقاق.
- تاريخ آخر بحث.
- تاريخ انتهاء البحث.
- حالة صلاحية البحث.
- حالة الطلب.

============================================================
5) التبويبات الرئيسية
============================================================

قسّم النموذج إلى خمسة تبويبات:

1. بيانات الطلب
2. الأسرة والبحث الاجتماعي
3. بنود المساعدة
4. المستندات والمرفقات
5. المراجعة والإرسال

كل تبويب يعرض حالة بصرية:

- غير مكتمل.
- مكتمل.
- يحتوي أخطاء.
- يحتاج مراجعة.

شروط سلوك التبويبات:

- الانتقال بينها لا يعيد تحميل الصفحة.
- البيانات لا تضيع.
- زر التالي يتحقق من التبويب الحالي.
- زر السابق لا يحذف أي بيانات.
- عند وجود أخطاء ينتقل النظام لأول تبويب به خطأ.
- يظهر Badge خطأ على التبويب غير الصحيح.
- يظهر نجاح على التبويب المكتمل.
- بعد إنشاء المسودة يمكن التنقل بحرية بين التبويبات.
- عند مغادرة الصفحة ببيانات غير محفوظة يظهر Confirm Modal مخصص، وليس Alert من المتصفح.

6) التبويب الأول: بيانات الطلب
============================================================

الحقول:

1. الأسرة المستفيدة
   - Searchable Select.
   - البحث بالاسم.
   - كود الأسرة.
   - الرقم القومي لرب الأسرة.
   - رقم الهاتف.
   - النتائج ضمن نطاق فرع أو منطقة المستخدم فقط.

2. مصدر الطلب
   - الأسرة مباشرة.
   - مندوب.
   - باحث اجتماعي.
   - فرع.
   - إدارة الجمعية.
   - جهة حكومية.
   - جمعية شريكة.
   - متبرع.
   - أخرى.

3. بيانات مقدم الطلب
   - الاسم.
   - الصفة بالنسبة للأسرة.
   - الهاتف.
   - تعبئة تلقائية عند توفر البيانات.

4. نوع الطلب
   - مساعدة وقتية.
   - مساعدة دورية.
   - مساعدة طارئة.

5. درجة الأولوية
   - عادية.
   - متوسطة.
   - مرتفعة.
   - عاجلة جدًا.

6. عنوان مختصر للطلب.

7. وصف الاحتياج.

8. تاريخ تقديم الطلب.

9. التاريخ المطلوب للتنفيذ، اختياري إلا إذا تطلبت الحالة ذلك.

10. سبب الاستعجال، يظهر ويلزم عند اختيار عاجلة جدًا.

11. هل الطلب مرتبط بحملة أو موسم؟
    - لا.
    - نعم.
    - عند نعم يظهر اختيار البرنامج أو الحملة.

12. الفرع المسؤول.

13. المندوب أو الموظف المسؤول.

14. ملاحظات داخلية لا تظهر للأسرة أو المتبرعين.

قواعد التبويب:

- لا يمكن المتابعة دون اختيار أسرة.
- نوع الطلب والأولوية والعنوان والوصف حقول إلزامية.
- لا ترسل أي إشعارات لمتبرعين.
- المسودة ليست طلبًا معتمدًا.

============================================================
7) التبويب الثاني: الأسرة والبحث الاجتماعي
============================================================

لا تعِد إدخال ملف الأسرة؛ اعرض ملخصًا من البيانات المسجلة.

أولًا: بيانات الأسرة المختصرة

- كود الأسرة.
- اسم رب الأسرة.
- الهاتف.
- العنوان العام.
- عدد أفراد الأسرة.
- عدد الأطفال.
- عدد المرضى.
- عدد ذوي الإعاقة.
- الفرع والمنطقة.
- المندوب المسؤول.
- حالة الأسرة.

ثانيًا: ملخص آخر بحث اجتماعي معتمد

- رقم البحث.
- نوع البحث.
- تاريخ إجرائه.
- تاريخ اعتماده.
- مدة الصلاحية.
- تاريخ الانتهاء.
- درجة الاستحقاق.
- متوسط دخل الفرد.
- صافي دخل الفرد إن وجد.
- توصية الباحث.
- قرار اللجنة.

ثالثًا: مؤشر صلاحية البحث

استخدم Research Validity Indicator بالحالات التالية:

1. ساري
   - لون نجاح.
   - يسمح باستكمال الطلب.

2. قارب على الانتهاء
   - لون تحذير.
   - يعرض الأيام المتبقية.
   - يسمح بالاستكمال مع تحذير.

3. منتهي
   - لون خطر.
   - يمنع إرسال الطلب العادي للمراجعة.
   - يسمح بحفظ المسودة.
   - يمكن استثناء الطلب الطارئ فقط بصلاحية خاصة وسبب مكتوب.

4. لا يوجد بحث معتمد
   - يمنع إرسال الطلب.
   - يسمح بالمسودة.
   - يظهر زر إنشاء بحث جديد لمن يملك الصلاحية.

رابعًا: المساعدات السابقة

اعرض آخر خمس مساعدات:

- النوع.
- التاريخ.
- القيمة.
- الحالة.
- وقتية أو دورية.

خامسًا: الطلبات المفتوحة والمشابهة

اعرض تحذيرًا إذا وجد:

- طلب مفتوح من نفس النوع.
- طلب قريب زمنيًا.
- مساعدة دورية نشطة من نفس التصنيف.
- طلب عاجل آخر غير مغلق.

لا تمنع التكرار دائمًا، لكن اطلب سبب إنشاء طلب مشابه وسجله.

============================================================

أنواع المرفقات:

- بطاقة رقم قومي.
- تقرير طبي.
- روشتة.
- عرض سعر.
- فاتورة.
- إيصال إيجار.
- عقد إيجار.
- شهادة قيد تعليمية.
- مستند دين.
- صور الحالة.
- صور المسكن.
- خطاب جهة.
- مستند آخر.

بيانات كل مرفق:

- نوع المستند.
- عنوان أو وصف.
- الملف.
- تاريخ المستند.
- تاريخ الانتهاء إن وجد.
- البند المرتبط به.
- حالة التحقق:
  - غير مراجع.
  - صحيح.
  - غير واضح.
  - منتهي.
  - مرفوض.
- ملاحظات.

قواعد الرفع:

- التخزين Private.
- لا توجد روابط عامة مباشرة.
- التحقق من نوع الملف الحقيقي.
- التحقق من الحجم.
- دعم PDF وJPG وJPEG وPNG.
- دعم أسماء الملفات العربية.
- إعادة تسمية الملفات داخليًا بأسماء آمنة.
- حفظ الاسم الأصلي.
- منع الملفات التنفيذية.
- Drag & Drop إن كان المكون الحالي يدعمه.
- Progress Bar.
- Preview للصورة وPDF إن أمكن.
- حذف الملف قبل إرسال الطلب.
- حذف الملف من التخزين إذا حُذف نهائيًا من المسودة.
- تسجيل من رفع الملف ووقت الرفع.

أنشئ Checklist للمستندات المطلوبة تلقائيًا حسب البنود.

مثال: عملية جراحية تقترح:

- تقرير طبي.
- عرض تكلفة.
- بيانات المستشفى.

يمكن حفظ المسودة مع نقص المستندات، لكن يمنع الإرسال إذا كانت مستندات إلزامية ناقصة.

============================================================
10) التبويب الخامس: المراجعة والإرسال
============================================================

اعرض مراجعة شاملة في صورة Sections واضحة:

1. ملخص الأسرة.
2. حالة البحث الاجتماعي.
3. بيانات الطلب.
4. قائمة البنود.
5. إجمالي القيمة التقديرية.
6. البنود الدورية والتزاماتها.
7. المستندات.
8. التحذيرات.
9. البيانات الناقصة.
10. الإقرار.

الإقرار:

"أقر بأن البيانات المدخلة والمستندات المرفقة صحيحة حسب ما تم تقديمه، وأن الطلب سيخضع للمراجعة والاعتماد وفق سياسات المنشأة."

يجب تحديد Checkbox الإقرار قبل الإرسال.

اعرض Validation Summary مجمعًا حسب التبويبات.

الأزرار:

- العودة للتعديل.
- حفظ كمسودة.
- إرسال للمراجعة.

قبل الإرسال اعرض Confirm Modal:

"بعد إرسال الطلب للمراجعة لن تتمكن من تعديل بياناته إلا إذا أعادته الإدارة للاستكمال. هل تريد المتابعة؟"

عند الإرسال:

1. تحقق من جميع البيانات على الخادم.
2. استخدم Database Transaction.
3. غيّر الحالة إلى submitted.
4. سجل submitted_at.
5. سجل submitted_by.
6. أضف سجلًا في Status History.
7. أطلق Event باسم AidRequestSubmitted.
8. أرسل إشعارًا داخليًا لمسؤول المراجعة فقط.
9. لا ترسل واتساب للمتبرعين.
10. يصبح الطلب Read Only بعد الإرسال، إلا إذا أعيد للاستكمال.

12) رقم الطلب

- لا يتغير بعد إنشائه.

14) العلاقات البرمجية
============================================================

AidRequest:
- belongsTo Family
- belongsTo Branch
- belongsTo creator User
- belongsTo submitter User
- hasMany AidRequestItems
- hasMany AidRequestAttachments
- hasMany AidRequestStatusHistories

AidRequestItem:

============================================================
16) الحفظ كمسودة
============================================================

زر "حفظ كمسودة" متاح من جميع التبويبات.

السلوك:

- يحفظ البيانات المتاحة الصحيحة.
- لا يشترط اكتمال النموذج.
- ينشئ الطلب في أول حفظ.
- يحدث الطلب بعد ذلك.
- يحفظ البنود والمرفقات.
- يعرض Toast نجاح.
- يعرض وقت آخر حفظ.
- لا يغير التبويب الحالي.
- لا يرسل إشعارات للمراجعين.

اعرض مثالًا:

آخر حفظ: منذ دقيقتين

لا تنفذ Auto Save الآن إلا إذا كان مستقرًا وبسيطًا؛ الأولوية للحفظ اليدوي الموثوق.

17) الصلاحيات
============================================================

- aid_requests.view_any
- aid_requests.view
- aid_requests.create
- aid_requests.update_draft
- aid_requests.submit
- aid_requests.update_returned
- aid_requests.delete_draft

القواعد:

- الاستثناء من انتهاء البحث يحتاج صلاحية وسببًا.

============================================================
18) الخصوصية والأمان
============================================================

- لا تعرض الرقم القومي كاملًا في نتائج البحث إلا بصلاحية.
- استخدم Masking مثل **********1234.
- الملفات Private.
- قراءة الملفات تمر عبر Authorization.
- تحقق من نطاق الأسرة والفرع على الخادم.
- لا تثق في IDs القادمة من الواجهة.
- سجل إنشاء وتعديل وإرسال الطلب.
- لا تسجل بيانات حساسة في Logs العامة.
- لا ترسل بيانات الأسرة في إشعارات غير آمنة.

  - الأولوية.

============================================================
22) قواعد التحقق قبل الإرسال
============================================================

لا يرسل الطلب إلا إذا:

- تم اختيار أسرة.
- الأسرة غير موقوفة.
- يوجد بحث معتمد وساري، أو استثناء طارئ مصرح به.
- بيانات الطلب الأساسية مكتملة.
- يوجد بند واحد على الأقل.
- جميع البنود صحيحة.
- القيم المالية صحيحة.
- المستندات الإلزامية موجودة.
- سبب التكرار مسجل عند وجود طلب مشابه.
- الإقرار محدد.

حفظ المسودة يسمح بالنقص.

نفذ:

- Validation خاص بكل تبويب.
- Validation شامل قبل الإرسال.
