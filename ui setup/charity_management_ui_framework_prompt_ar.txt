برومبت تنفيذ واجهة نظام إدارة منشأة خيرية
مخصص لوكيل البرمجة: GPT-5.4 Mini
المهمة الحالية: تأسيس الواجهة ونظام التصميم قبل تنفيذ منطق الأعمال

============================================================
1. الهدف العام
============================================================

أنشئ الأساس البصري والتقني الكامل لواجهة نظام ويب لإدارة منشأة خيرية.

المطلوب في هذه المرحلة:

1. نظام تصميم موحد Design System.
2. هيكل التطبيق العام App Shell.
3. شاشة تسجيل الدخول.
4. قائمة جانبية RTL قابلة للطي والإخفاء.
5. حاوية المحتوى الرئيسية.
6. مكتبة مكونات UI قابلة لإعادة الاستخدام.
7. تفضيلات الواجهة لكل مستخدم.
8. حالات التحميل وانقطاع الإنترنت وانتهاء الجلسة.
9. صفحة UI Kit مرجعية.
10. شاشات تجريبية حقيقية لاختبار النظام البصري.

لا تنفذ منطق إدارة الأسر أو التبرعات أو الاعتمادات في هذه المرحلة.

المعادلة المطلوبة:

Design System
+ App Shell
+ Reusable Components
+ Global States
+ Real UI Test Screens
= Stable Internal UI Framework

============================================================
2. بيئة العمل
============================================================

استخدم:

- Laravel 13
- Livewire
- MySQL
- Blade Components
- Tailwind CSS
- Vite
- واجهة عربية RTL
- JavaScript بسيط أو Alpine.js عند الحاجة فقط
- Full-page Livewire Components
- wire:navigate لتجربة تنقل شبيهة بالـSPA

ممنوع استخدام:

- React
- Vue
- Inertia
- Bootstrap
- SPA Framework خارجي
- CSS عشوائي موزع داخل الصفحات
- تكرار نفس مكونات الواجهة
- بناء التطبيق كله في Livewire Component واحد ضخم

شروط التنقل:

- لا يوجد Full Page Refresh عند التنقل الداخلي.
- الروابط الداخلية تستخدم wire:navigate.
- زر الرجوع والتقدم في المتصفح يعمل.
- يظهر شريط تحميل علوي عند التنقل.
- تحافظ القائمة الجانبية على حالتها أثناء التنقل.

============================================================
3. قواعد العمل والتوثيق
============================================================

قبل كتابة الكود:

1. افحص المشروع الحالي بالكامل.
2. لا تحذف أو تستبدل ملفات مهمة دون داعٍ.
3. إذا كان المشروع جديدًا، أنشئ الهيكل المطلوب بطريقة منظمة.
4. أنشئ ملف UI_IMPLEMENTATION_PLAN.md قبل التنفيذ.
5. حدّث بعد كل مرحلة:
   - PROGRESS.md
   - TASKS.md
   - DECISIONS.md
6. أنشئ:
   - UI_SYSTEM.md
   - COMPONENTS.md
   - THEME_TOKENS.md
   - ACCESSIBILITY.md
7. لا تنتقل إلى مرحلة جديدة قبل اختبار المرحلة الحالية وإصلاح أخطائها.

4. اللغة واتجاه الواجهة
============================================================

- الواجهة عربية بالكامل.

6. شاشة تسجيل الدخول
============================================================

أنشئ شاشة تسجيل دخول Full Screen مستقلة.

التصميم:

- خلفية متدرجة من البني الداكن إلى البني الدافئ.
- شعار المنشأة في المنتصف.
- أسفل الشعار Glass Card لتسجيل الدخول.
- البطاقة في مركز الشاشة.
- عرض تقريبي 420px إلى 460px.
- Border Radius حوالي 24px.
- Blur متوازن.
- Padding مريح.
- تباين واضح.

المكونات:

- الشعار.
- عنوان تسجيل الدخول.
- حقل اسم المستخدم.
- حقل كلمة المرور أو رمز الدخول.
- إظهار وإخفاء كلمة المرور.
- خيار تذكر الدخول إن كان مناسبًا.
- زر دخول رئيسي عريض.
- Loading State داخل الزر.
- رسائل Validation داخل البطاقة.
- دعم Enter.
- Focus واضح.
- Auto Complete مناسب وآمن.
- لا تستخدم Alert من المتصفح.
- لا تعرض صفحة خطأ خام.

افصل Layout تسجيل الدخول عن Layout النظام الداخلي.

7. هيكل التطبيق App Shell
============================================================

أنشئ App Shell موحدًا يحتوي على:

- Sidebar.
- Main Content Container.
- Top Loading Progress Bar.
- Toast Container.
- Global Modal Layer.
- Offline Overlay.
- Session Expired Modal.
- Breadcrumb أو Page Header.
- User Preferences Modal أو Drawer.

التقسيم في Desktop:

- Sidebar على اليمين.
- عرض القائمة المفتوحة: 320px.
- المسافة بينها وبين المحتوى: حوالي 10px.
- هامش خارجي: 10px إلى 12px.
- القائمة مستديرة الحواف.
- حاوية المحتوى مستديرة الحواف.
- التطبيق يملأ ارتفاع نافذة المتصفح.
- Scroll المحتوى داخل الحاوية الرئيسية.
- القائمة لها Scroll داخلي عند الحاجة.
- جزء المستخدم مثبت أسفل القائمة.

المقاسات:

- Sidebar Open: 320px
- Sidebar Collapsed: 88px إلى 92px
- Shell Gap: 10px
- Outer Gap: 10px إلى 12px
- Large Radius: 22px إلى 26px
- Medium Radius: 14px إلى 18px

11. تفضيلات الواجهة
============================================================

1. اختيار Accent Color.
2. حجم الخط:
   - صغير
   - متوسط
   - كبير
3. كثافة الواجهة:
   - مضغوط
   - متوازن
   - واسع
4. حالة Sidebar:
   - مفتوحة
   - مطوية
5. خيار Reduced Motion.

التغيير يظهر فورًا دون Refresh.

استخدم خصائص مثل:

data-accent
data-font-size
data-ui-density
data-reduced-motion

أحجام الخط المقترحة:

- Small: 14px
- Medium: 16px
- Large: 18px

الكثافة:

Compact:
- Control Height: 36px
- Table Row: 40px

Balanced:
- Control Height: 44px
- Table Row: 48px

Spacious:
- Control Height: 52px
- Table Row: 58px

ضع القيم النهائية في Tokens.

============================================================
15. اكتشاف انقطاع الإنترنت
============================================================

نفذ نظامًا موحدًا، ولا تعتمد فقط على navigator.onLine.

استخدم:

1. Browser online/offline events.
2. Endpoint خفيف مثل /health/ping.

عند الانقطاع:

- Overlay يغطي التطبيق.
- خلفية شفافة مع Blur.
- يمنع التفاعل.
- Modal في المنتصف.
- عنوان: "انقطع الاتصال بالإنترنت"
- نص: "سيتم استئناف العمل تلقائيًا عند عودة الاتصال."
- مؤشر إعادة محاولة.
- آخر وقت اتصال ناجح إن أمكن.

عند العودة:

- افحص الخادم فعليًا.
- لا تخفِ Overlay إلا بعد نجاح الفحص.
- اعرض Toast: "تمت استعادة الاتصال".
- لا تعمل Reload كامل إلا عند ضرورة تقنية واضحة.

نفذ النظام من مكان مركزي واحد.

============================================================
16. انتهاء جلسة المستخدم
============================================================

عند انتهاء Session أو رجوع 419:

- لا تعرض صفحة الخطأ الافتراضية.
- اعترض الخطأ عالميًا.
- اعرض Modal غير قابل للإغلاق.

المحتوى:

العنوان:
"انتهت جلسة العمل"

النص:
"انتهت الجلسة بسبب عدم النشاط. يرجى تسجيل الدخول مرة أخرى لحماية بيانات النظام."

الأزرار:

- تسجيل الدخول من جديد.
- نسخ البيانات غير المحفوظة إذا أمكن.

السلوك:

- احفظ الرابط الحالي.
- أعد المستخدم لصفحة الدخول.
- بعد الدخول أعده للرابط السابق.
- لا تسمح بالاستمرار بجلسة منتهية.
- لا تكرر الطلب بلا نهاية.
- لا تستخدم Alert.

- Required Indicator موحد.
- Help Text.
- Validation Message.
- أحجام مرتبطة بـUI Density.
- مسافات مريحة.
- Focus Ring من Accent.
- الحقول الطويلة مقسمة إلى Sections.
- لا تضع عددًا ضخمًا من الحقول في Card واحدة.

============================================================
22. Responsive Design
============================================================

اختبر على:

- Desktop كبير.
- Laptop.
- Tablet.
- Mobile.

السلوك:

Desktop:
- Sidebar مفتوحة أو مطوية.
- Content بجانبها.

Tablet:
- Sidebar تبدأ مطوية إذا كان ذلك أنسب.

Mobile:
- Sidebar Drawer.
- Content Full Width.
- الجداول Cards أو Horizontal Scroll مدروس.
- Modals لا تتجاوز الشاشة.
- الأزرار قابلة للاستخدام.
- لا يوجد قص للنص العربي.

============================================================
23. Accessibility
============================================================

نفذ:

- Keyboard Navigation.
- Focus Visible.
- aria-label عند الحاجة.
- Labels مرتبطة بالحقول.
- تباين ألوان واضح.
- لا تعتمد على اللون وحده.
- Escape يغلق Modals القابلة للإغلاق.
- Session Expired Modal لا يغلق.
- Reduced Motion.
- Click Targets مناسبة.
