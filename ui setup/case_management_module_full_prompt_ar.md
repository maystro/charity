# برومبت تنفيذ وحدة «إدارة الحالات» كاملة

**مخصص لوكيل البرمجة:** GPT-5.4 Mini  
**المشروع:** نظام إدارة منشأة خيرية  
**بيئة العمل:** Laravel 13 + Livewire + MySQL + Tailwind CSS  
**لغة الواجهة:** العربية RTL  
**نمط التطبيق:** SPA-like باستخدام Livewire Full-page Components و`wire:navigate` دون إعادة تحميل كامل للصفحة  
**الحالة الحالية:** تم الانتهاء من الواجهة العامة وUI Framework، ويجب استخدامهما كما هما دون إعادة تصميم أو بناء نمط موازٍ.

---

# 1. الهدف العام

المطلوب تنفيذ وحدة **إدارة الحالات** كاملة، وهي المجموعة الظاهرة في القائمة الجانبية وتحتوي على:

1. **الأسر والحالات**
2. **البحوث الميدانية**
3. **طلبات المساعدة**
4. **الزيارات والمتابعة**

هذه الوحدة هي القلب الرئيسي للنظام، وتدير دورة المستفيد من أول تسجيل الأسرة حتى إعادة التقييم والمتابعة.

## دورة العمل العامة

```text
إضافة أسرة
→ التحقق من عدم التكرار
→ استكمال بيانات الأسرة
→ إنشاء بحث ميداني
→ إرسال البحث للمراجعة
→ اعتماد أو رفض الحالة
→ إنشاء طلب مساعدة
→ مراجعة الطلب
→ إحالته لاحقًا للجنة الاعتماد
→ متابعة التنفيذ لاحقًا
→ زيارة متابعة
→ إعادة تقييم الأسرة عند انتهاء صلاحية البحث
```

يجب الفصل بوضوح بين:

- ملف الأسرة الدائم.
- البحث الاجتماعي المؤقت وله مدة صلاحية.
- طلب المساعدة المرتبط باحتياج محدد.
- بند المساعدة داخل الطلب.
- الزيارة الميدانية.
- المستندات.
- سجل الحركة.

# 2. قواعد إلزامية قبل التنفيذ

قبل تعديل الكود:

1. افحص المشروع الحالي بالكامل.
2. افحص جميع مكونات UI Framework الحالية.
3. استخدم المكونات الموجودة مثل:
   - `x-ui.button`
   - `x-ui.input`
   - `x-ui.select`
   - `x-ui.searchable-select`
   - `x-ui.modal`
   - `x-ui.tabs`
   - `x-ui.table`
   - `x-ui.card`
   - `x-ui.badge`
   - `x-ui.alert`
   - `x-ui.file-upload`
   - `x-ui.stepper`
   - `x-ui.empty-state`
   - `x-ui.skeleton`
4. لا تكتب عناصر بكلاسات Tailwind طويلة داخل الصفحات إذا كان لها مكون موجود.
5. إذا احتجت مكونًا جديدًا:
   - أنشئه في مكتبة UI.
   - أضفه إلى `/developer/ui-kit`.
   - وثقه في `COMPONENTS.md`.
6. لا تغير الهوية البصرية أو App Shell أو نظام Accent أو UI Density.
7. لا تستخدم React أو Vue أو Inertia أو Bootstrap.
8. كل التنقلات تستخدم `wire:navigate`.
9. ممنوع `alert()` و`confirm()` ونوافذ المتصفح الافتراضية.
10. أنشئ قبل التنفيذ:
    - `CASE_MANAGEMENT_IMPLEMENTATION_PLAN.md`
11. أنشئ للتوثيق:
    - `CASE_MANAGEMENT_MODULE.md`
12. حدّث بعد كل مرحلة:
    - `PROGRESS.md`
    - `TASKS.md`
    - `DECISIONS.md`
13. لا تنتقل لمرحلة جديدة قبل اختبار الحالية.

# 5. نظام الترقيم

أنشئ أرقامًا فريدة وآمنة:

```text
FAM-2026-000001  رقم الأسرة
RSR-2026-000001  رقم البحث
AR-2026-000001   رقم طلب المساعدة
VIS-2026-000001  رقم الزيارة
```

الشروط:

- لا تستخدم `count + 1`.
- آمن مع تعدد المستخدمين.
- لا يتكرر.
- لا يتغير بعد الإنشاء.
- استخدم Service مستقلة أو جدول Sequences.
- يمكن جعل Prefix قابلًا للتعديل مستقبلًا.


- الرقم القومي.

- تشابه الاسم.
- اسم الزوج/الزوجة.
- العنوان.

- الموقع الجغرافي.

- تطابق مؤكد.
